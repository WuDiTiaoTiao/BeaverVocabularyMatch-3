# 词汇消消乐云端进度同步设计

日期：2026-11-16

状态：已批准，待实施

## 1. 背景

当前网站部署在 GitHub Pages，游戏进度保存在浏览器 `localStorage`。这种方式能区分不同浏览器配置，但不能在手机、平板和电脑之间自动同步，也不能区分共用同一浏览器配置的不同用户。

本次改动在保留 GitHub Pages 静态部署和游客模式的基础上，引入 Supabase 邮箱验证码登录与云端进度存储。用户不登录仍可完整游玩；登录后可以跨设备恢复当前词书挑战。

## 2. 目标

- 支持邮箱六位验证码登录，不要求设置密码。
- 保留游客模式和当前本机保存机制。
- 登录后自动把本机进度与云端进度合并。
- 同一账号在不同设备登录后可恢复当前挑战。
- 断网或云端故障时不影响游戏，本机进度始终优先落盘。
- 用户只能访问自己的进度。
- 保持现有 GitHub Pages 部署方式，不增加自建服务器。
- 保持现有游戏规则、动画、词库、复习页面和响应式布局。

## 3. 非目标

- 不提供用户名和密码登录。
- 不提供社交平台登录。
- 不记录全量历史成绩、排行榜或好友系统。
- 不支持一个账号同时保留多本未完成的挑战词书。
- 不在本次实现账号注销；用户可以退出登录，后续可单独增加注销流程。

## 4. 技术方案选择

采用 Supabase：

- Supabase Auth 负责邮箱验证码和会话。
- Supabase Postgres 负责保存一条当前挑战记录。
- Row Level Security（RLS）限制用户只能操作自己的记录。
- 前端直接使用公开的 Supabase URL 与 `anon key`。
- `service_role key` 不进入网页、GitHub 仓库或浏览器。

网站继续由 GitHub Pages 托管，不购买或维护独立服务器。

## 5. 系统结构

### 5.1 现有模块

- `game.js`：纯游戏规则与状态转换。
- `challenge-progress.js`：本机挑战记录的编码、校验和保存。
- `ui.js`：页面渲染与用户交互。

### 5.2 新增模块

- `auth.js`：初始化 Supabase、发送验证码、验证验证码、恢复会话和退出登录。
- `cloud-progress.js`：读取、合并、上传、替换和删除云端挑战。
- `sync-model.js`：纯函数形式的本机/云端合并决策，便于独立测试。
- `supabase/schema.sql`：数据表、索引、RLS 策略和必要的数据库函数。
- `supabase/SETUP.md`：Supabase 项目的配置步骤。

Supabase 客户端以固定版本的 ESM 模块动态加载。云端模块加载失败时，核心游戏仍然启动并继续使用本机保存，避免第三方脚本故障导致整个网站不可用。

## 6. 数据模型

表名：`challenge_progress`

每个登录用户最多有一条当前挑战记录，`user_id` 为主键：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `user_id` | `uuid` | 对应 `auth.users.id`，主键 |
| `book_id` | `text` | `ielts`、`cet6`、`postgrad` 或 `cet4` |
| `scope` | `text` | `frequent` 或 `full` |
| `seed` | `bigint` | 当前挑战随机种子 |
| `completed_pair_ids` | `jsonb` | 已完成词对 ID 数组 |
| `score` | `integer` | 当前整本挑战得分 |
| `correct_matches` | `integer` | 正确配对次数 |
| `attempts` | `integer` | 总尝试次数 |
| `client_updated_at` | `timestamptz` | 客户端记录更新时间，用于合并判断 |
| `updated_at` | `timestamptz` | 数据库写入时间 |

数据库约束保证词书、范围、数字字段和数组结构有效。完成整本词书或确认重置后删除该行，因此下一次打开网站会重新显示词书选择页。

## 7. 身份验证流程

1. 游客点击页头“登录同步”。
2. 输入邮箱并请求验证码。
3. Supabase 向邮箱发送六位验证码。
4. 用户在原页面输入验证码。
5. 前端调用 Supabase 验证接口并保存会话。
6. 登录成功后立即开始本机/云端进度协调。
7. Supabase 自动恢复有效会话，用户再次打开网站无需重复登录。

验证码界面包含重新发送倒计时、修改邮箱、验证码错误、验证码过期和发送频繁等状态。登录失败不影响游客游戏。

## 8. 同步与冲突规则

### 8.1 保存顺序

每次有效进度变化采用以下顺序：

1. 立即保存到 `localStorage`。
2. 更新界面状态。
3. 登录且在线时异步同步到 Supabase。

云端请求不得阻塞匹配动画、计时器或下一局操作。

### 8.2 同一本词书

本机和云端的 `book_id`、`scope` 相同时：

- `completed_pair_ids` 取去重后的合集。
- 挑战总数与已完成挑战数由合并后的词对数量重新计算。
- `seed` 使用 `client_updated_at` 更新的一侧，保证恢复后的词块顺序稳定。
- `score`、`correct_matches`、`attempts` 使用 `client_updated_at` 更新的一侧，避免重复相加。
- 合并结果同时写回本机和云端。

数据库提供原子合并函数，在行锁内读取并更新，防止两台设备同时保存时丢失已完成词对。重复提交同一结果不会重复计数。

### 8.3 不同词书

本机与云端存在不同的未完成词书时，不自动覆盖。页面显示冲突弹窗，列出两边的：

- 词书与范围。
- 已完成配对数/总数。
- 最近更新时间。

用户选择：

- “继续云端进度”：云端覆盖本机当前挑战。
- “使用本机进度”：明确替换云端当前挑战。

只有用户选择后才写入，关闭弹窗则保持两边原状。

### 8.4 离线与重试

- 离线时显示“离线保存”，继续使用本机记录。
- 浏览器触发 `online` 事件、页面重新打开或重新登录时重试。
- 同一版本的待同步记录只保留最新一份，不建立无限重试队列。
- 同步失败依次在 5 秒、30 秒、120 秒后重试；三次仍失败则等待重新联网、重新打开页面或用户重新登录，不每秒重复请求。

## 9. 重置、完成和退出

- “重置挑战词书”在登录状态下同时删除本机与云端记录。
- 云端删除失败时不清除本机记录，并在确认弹窗内显示错误。
- 游客状态只删除本机记录。
- 完成整本词书后立即在本机记录当前账号的“待删除云端挑战”标记并清除本机当前挑战，再显示总成绩与词书选择入口；在线时异步删除云端记录，失败或离线时在后续联网/打开页面后先重试删除，避免旧云端进度复活。
- 退出登录只结束 Supabase 会话，不主动删除本机挑战。
- 退出后用户可以继续以游客身份使用当前设备上的进度。

## 10. 界面设计

### 10.1 页头账户入口

- 游客：显示“登录同步”。
- 已登录：显示邮箱缩写和云端状态。
- 状态文案：`已同步`、`同步中`、`离线保存`、`同步失败`。

### 10.2 登录弹窗

- 第一步输入邮箱。
- 第二步输入六位验证码。
- 支持修改邮箱和倒计时后重新发送。
- 登录成功后弹窗关闭，游戏不中断。

### 10.3 冲突弹窗

并列展示本机和云端记录，按钮使用明确命令文案。替换云端属于有损操作，按钮需要二次确认。

### 10.4 响应式要求

- 桌面端账户入口位于页头右侧。
- 平板端不增加新的侧栏。
- 手机端账户按钮和同步状态压缩为紧凑行，不遮挡词书进度、计时器或词块。
- 所有弹窗适配安全区域和小屏滚动。

## 11. 安全设计

- `challenge_progress` 开启 RLS。
- 查询、插入、更新和删除策略均要求 `auth.uid() = user_id`。
- 数据库合并函数使用当前认证用户 ID，不接受调用方伪造 `user_id`。
- `service_role key` 不出现在前端。
- 邮箱在界面中只显示必要的脱敏形式。
- 控制台日志不输出验证码、访问令牌或完整会话对象。
- Supabase 允许的站点地址与跳转地址仅配置正式 GitHub Pages 域名和本地开发地址。

## 12. 错误处理

- Supabase 初始化失败：进入游客模式并显示非阻塞提示。
- 验证码发送/校验失败：保留用户输入并显示可操作原因。
- 云端读取失败：使用本机记录，不打开空白游戏。
- 云端保存失败：保留待同步标记，并继续本机游戏。
- 记录格式无效：拒绝使用异常云端数据，不覆盖有效本机记录。
- 删除失败：保持当前挑战，不显示成功状态。
- 词库版本变化导致部分 pair ID 失效：按当前词库过滤未知 ID 后再同步。

## 13. Supabase 配置要求

实施时需要用户创建一个 Supabase 项目，并完成：

1. 在 SQL Editor 运行仓库提供的 `supabase/schema.sql`。
2. 启用 Email 登录。
3. 将邮件模板设置为六位验证码形式。
4. 配置正式站点 URL：`https://wuditiaotiao.github.io/KaoyanVocabularyMatch-3/`。
5. 配置本地开发跳转地址。
6. 将项目 URL 和公开 `anon key` 填入前端配置。

公开 `anon key` 可以进入静态网站；任何 `service_role key` 都不得提供或提交。

## 14. 测试计划

### 14.1 单元测试

- 本机记录与云端记录校验。
- 同词书合并取 pair ID 合集。
- 重复同步保持幂等。
- 不同词书返回冲突而不修改记录。
- 未知 pair ID 过滤。
- 更新时间选择得分和统计字段。
- 登录、退出和会话恢复状态转换。
- 离线待同步和恢复重试。

### 14.2 数据库测试

- 用户只能访问自己的行。
- 未登录用户不能访问任何云端进度。
- 原子合并在并发请求下不丢失 pair ID。
- 非法词书、范围和负数统计被拒绝。

### 14.3 浏览器测试

- 游客可以不登录开始挑战。
- 登录后本机进度上传并跨刷新恢复。
- 第二设备登录后恢复同一进度。
- 不同词书显示冲突弹窗。
- 离线游玩后恢复网络完成同步。
- 退出不删除本机进度。
- 重置同时清除本机和云端。
- 手机 390px、平板和桌面布局无重叠或横向溢出。
- 保留并通过现有全部游戏测试。

## 15. 发布与回滚

1. 先在 Supabase 创建表、RLS 和数据库函数。
2. 使用本地 Supabase 项目配置完成联调。
3. 在正式 Supabase 项目验证邮箱验证码和权限隔离。
4. 通过 GitHub 网站提交静态文件与 SQL 配置。
5. 等待 GitHub Pages 部署成功后验证正式站点。

如果云同步出现故障，前端降级为游客模式；核心游戏和本机进度不依赖 Supabase 可用性。回滚前端不会删除云端记录。

## 16. 验收标准

- 不登录可正常完成全部现有游戏流程。
- 登录用户在另一设备登录同一邮箱后可以恢复当前词书进度。
- 两台设备的同词书已完成 pair ID 不会互相覆盖或重复计数。
- 不同词书不会被静默覆盖。
- 断网不丢失已完成配对。
- 任何用户无法读取或修改其他用户进度。
- Supabase 不可用时网站仍能进入并游玩。
- 手机、平板和桌面布局均可用。
- 自动化测试和正式站点验收全部通过。
